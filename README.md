# farelog · 1월 일본 항공권 기록

인천–나고야·삿포로 왕복 항공권의 조회 후보 최저가, 원화·엔화 표시 요금, 전일 변화율을 보는 정적 웹앱입니다. 토스의 여백, 밝은 배경, 카드 구성과 파란 강조색을 참고한 독립 디자인이며 토스와 관계가 없습니다.

**서버, DB, API 키 없이 동작합니다.** 브라우저는 빌드된 JSON만 읽습니다. 항공권 조회는 ChatGPT의 Skyscanner 연결 도구에서 수행하고, 결과를 저장한 Git 커밋이 Netlify 재배포를 일으키는 구조입니다. 현재 이 프로젝트만으로 예약 조회나 GitHub 쓰기 권한이 연결되지는 않습니다.

## 먼저 실행하기

Node.js 22 이상이 필요합니다. 별도 npm 설치 단계나 런타임 라이브러리가 없습니다. 차트는 반응형 SVG이며 폰트는 Noto Sans KR(온라인 로드 실패 시 시스템 글꼴)입니다.

```bash
npm test
npm run dev
```

`http://localhost:5173`에서 확인합니다. 데이터나 소스 수정 후에는 개발 서버를 다시 실행합니다. HTML을 파일 더블클릭으로 열면 JSON fetch가 차단될 수 있으므로 로컬 서버를 사용하세요.

```bash
npm run build
```

정적 배포 결과는 `dist/`에 생성됩니다. ZIP에 미리 빌드한 `dist/`도 포함되어 있지만 Git에서는 제외하며 배포 때 새로 생성합니다.

## GitHub → Netlify 연결

1. 새 GitHub 저장소를 만들고, **이 README와 package.json이 저장소 최상위**에 오도록 압축을 푼 프로젝트 내용을 올립니다. `.github/`, `.gitignore` 같은 숨김 항목도 포함합니다.
2. Netlify에서 Git 저장소 가져오기를 선택하고 이 저장소와 기본 브랜치를 연결합니다.
3. Base directory는 비움, Build command는 `npm test && npm run build`, Publish directory는 `dist`입니다. `netlify.toml`에 이미 설정되어 있습니다. Node 버전은 22입니다.
4. 환경 변수나 비밀키는 필요 없습니다. 연결된 브랜치에 새 기록을 커밋하면 Netlify가 검증 후 배포합니다.
5. 최초 배포 후 원화/엔화, 직항, 기간/도시 필터, CSV, Skyscanner 링크를 확인합니다.

GitHub Actions는 빌드 검증만 합니다. 배포는 Netlify Git 연동이 담당하므로 Netlify 토큰을 GitHub에 넣을 필요가 없습니다. 실패한 빌드는 새 버전으로 배포되지 않습니다.

## 화면 기능

- 도시별 최신 후보 최저가, 동일 일정의 KRW와 JPY, 항공사, 직항/경유, 날짜와 동률 일정 링크
- 전날 대비 금액·변화율, 최저가 일정 변경 여부
- 통화별 가격 그래프, 7일/30일/전체, 직항 필터, 도시별 이력, CSV 내보내기
- 미조회·조회 실패·엔화 누락·오래된 데이터 구분
- 모바일 레이아웃, 키보드 조작, 차트 점 상세 정보, 외부 링크 새 창 열기

## 초기 실제 기록과 기준

- 나고야: 2026-10-28~11-02 기존 대화의 Skyscanner 최저가 요약 복원 + 11-03 새 월간 응답
- 삿포로: 2026-11-03 새 월간 응답부터 시작
- 11-03 나고야: 1월 13~19일, 제주항공 직항, 317,699원 / 37,307엔. 13~20일도 같은 요금.
- 11-03 삿포로: 1월 13~19일 후보, 제주항공·피치항공 경유, 438,592원 / 51,504엔.
- 과거 복원 기록은 `provenance: restored`, `coverage: best-summary-only`입니다. 당시 원본 API 응답과 정확한 시간은 없으며, 정렬용 00:00은 실제 조회 시간이 아닙니다. 10월 28일 JPY는 미조회이므로 null입니다.
- 새 조회 원본은 `data/evidence/`에 있습니다. 임의의 예시 요금이나 생성된 추세는 섞지 않았습니다.

`config.json`의 기본 조건은 **2027년 1월 안에 출국·귀국, ICN 출발, 성인 1명 일반석, 3~13박 후보**입니다. 이전 조사 기준인 2주 미만을 적용했습니다. 상한 없이 3박 이상으로 보고 싶다면 `maxNights`를 30으로 바꾸세요. 다만 복원 기록에는 당시 조건에서 제외했던 후보 전체가 없으므로 **과거 변화율을 다른 조건의 값으로 재해석할 수 없습니다.** 조건 변경 시 별도 데이터 계열로 시작하는 것이 정확합니다.

**표현상 한계:** 월간 도구는 모든 날짜의 확정 견적이 아니라 제한된 예상가 후보를 제공합니다. 이 화면의 최저가는 반환된 후보 중 최저가입니다. 날짜 차이로 체류 길이를 계산하며, 경유편의 현지 도착일/시각이 없어 실제 3박 이상 체류는 예약 화면에서 확인해야 합니다. 수하물 포함 여부, 경유 횟수, 출도착 시각은 미확인입니다.

엔화는 별도 JPY 응답의 동일 quote ID를 연결한 표시가입니다. KRW 환산값이 아니며 일본 시장의 판매가나 실제 엔화 결제를 보장하지 않습니다. 엔화가 더 싼 다른 후보를 별도로 선정하지 않고 **원화 최저가 일정**을 기준으로 두 통화를 보여줍니다.

## 새 조회를 기록하는 방법

`docs/COLLECTION.md`와 `AGENTS.md`에 추후 에이전트가 따라야 할 수집 절차가 있습니다.

1. 동일 조건으로 NGO/CTS를 각각 KRW/JPY로 조회합니다(총 4회).
2. 도구가 반환한 실제 JSON을 파일에 저장합니다. 전체 응답 또는 `structuredContent` 모두 지원합니다.
3. 실제 조회 시각을 넣어 도시별로 가져옵니다.

```bash
npm run import -- --krw /tmp/NGO-KRW.json --jpy /tmp/NGO-JPY.json --at 2026-11-04T09:30:00+09:00
npm run import -- --krw /tmp/CTS-KRW.json --jpy /tmp/CTS-JPY.json --at 2026-11-04T09:32:00+09:00
npm test
npm run build
git add data/observations data/evidence
git commit -m "data: record 2026-11-04 flight quotes"
git push
```

시간은 예시입니다. 실제 조회 시각으로 바꿉니다. JPY 응답에 동일 quote ID가 없으면 환산하지 않고 null을 저장합니다. JPY 조회가 실패했다면 `--jpy`를 생략할 수 있습니다. KRW 조회 자체가 실패하면 오류 기록을 남기는 방법은 COLLECTION.md를 참고합니다.

같은 날 재조회해도 파일을 덮어쓰지 않습니다. 하루의 마지막 기록이 화면에 대표값으로 나오고 이전 원본은 보존합니다. 과거 데이터는 고치지 않고 새 관측을 추가하는 방식을 권장합니다.

## 변화율 계산

`(당일 최저 KRW/JPY − 바로 전 달력일의 최저 KRW/JPY) / 전날 값 × 100`입니다. 한국 날짜 기준, 소수점 두 자리로 표시합니다. 전날 기록이 없으면 과거의 다른 날과 대신 비교하지 않습니다. 하루에 여러 번 조사하면 최신 시간 기준이며 마지막 조사 실패를 이전 성공 값으로 가리지 않습니다. 날짜 조합은 매일 달라질 수 있어, 같은 항공편의 가격 변동과는 다릅니다. 동률 일정에 공통 일정이 있으면 날짜 변경으로 표시하지 않습니다.

## 앞으로의 예약 작업 연결

저장소 생성 후 ChatGPT에 **저장소 URL, 사용할 브랜치, 매일 실행할 한국 시간**을 알려주고 GitHub 연결 권한을 제공합니다. 그때 기존 항공권 예약 작업을 이 저장소에 실제 기록을 추가하는 작업으로 수정해야 합니다. 지금은 웹앱과 데이터 형식만 완성한 상태이며, 기존 예약 작업이나 외부 저장소를 수정하지 않았습니다. Skyscanner/GitHub 연결을 예약 실행 환경에서 사용할 수 있는지도 첫 자동 실행에서 확인해야 합니다.
